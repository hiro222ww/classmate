## 1. Classmateの特徴と強み（コード・文言根拠）

| 項目 | 根拠に基づく事実 |
|---|---|
| コンセプト | 同年代と気軽に通話できる音声コミュニティ（`lib/seo.ts` / `app/about`） |
| 対象 | 18歳以上・高校生以下不可（利用規約） |
| クラス | テーマ別・最大5人程度の少人数グループ通話（about） |
| マイクラス | ホームの参加中クラス導線（実装済みUI） |
| ランダム通話 | ホームから通話/チャットへ（少人数・最大5人程度。古い「3人で自動開始」説明は使わない） |
| 招待 | クラス内で招待リンク共有（Room実装） |
| 初回体験 | 表示名+年齢の最小プロフィール → ホーム（マイクラス／ランダム通話） |
| 差別化 | 「同年代 × 少人数音声 × クラス形式」。出会い目的・連絡先交換は規約上NG |

**想像で補っていないこと**: 利用者数・口コミ・未実装のマッチングAI等。

### キャッチコピー5案
1. 同年代と、気軽に声でつながる場所。
2. テキストの先に、雑談の席を。
3. 少人数だから、最初の一言が出しやすい。
4. 友だちづくりを、通話から始める。
5. ひとりの夜に、短い会話を。

## 2. 推奨するSNS戦略（X最優先）

**北星KPI**: 登録数より **通話体験者数 → 継続利用率**。

### 最初の10人
- 運営者の知人・同じ個人開発者コミュニティへ正直な紹介（架空実績なし）
- Xで開発ストーリー＋質問投稿を交互に出し、リプが来たら丁寧に会話
- 「一緒に短時間だけ通話してフィードバック欲しい」と明示（強制しない）
- 招待リンクで2人以上の小さなクラスを先に作る

### 最初の100人
- 共感・質問でリーチ → 週2〜3回だけサービス紹介/参加促進（宣伝過多を避ける）
- プロフィール固定にClassmate説明＋UTM付きリンク
- 未確定の週次雑談枠は「需要調査」として聞き、確定後にだけ告知
- 通話が空の時間帯は「短時間でOK」「覗くだけOK」を繰り返し心理ハードルを下げる

### 投稿テーマ例
大人の友だち不足 / 声で話す機会の少なさ / 少人数の安心感 / 個人開発の率直な進捗 / 初対面の話題づくり

### 共感 vs 宣伝
目安 **共感・質問 6 : 紹介・参加・ストーリー 4**。毎回URLは貼らない。

### 頻度・時間（仮説・要検証）
1日1〜2件。仮説枠: **12:00–13:00** と **20:30–21:30 JST**（昼リーチ／夜の寂しさ・暇）。

### フォロワー少の認知
質問・共感でリプを取りにいく。引用されやすい短文。他アカへの無差別絡み・自動フォローはしない。

### 通話相手が少ない対策
正直に初期だと伝える／招待で少人数を先に成立／短時間OK／「週1雑談」は確定前に募集のみ。

## 3. 投稿生成プロンプト改善
- 投稿タイプを5種に拡張: empathy / question / intro / invite / story
- 事実ベースの製品コンテキスト（マイクラス・ランダム通話・招待・18+）
- `expected_action` を必須化、CTAは空可
- 日次でタイプをローテーション
- ヒューリスティック品質スコア＋予算内1回までの再生成

---

## 4. 14日カレンダー
- 管理画面「14日カレンダー投入」または `POST /api/admin/marketing/calendar`
- すべて **draft**（承認前に外部公開しない）
- イベントは「開催未確定」と明記した需要調査投稿のみ

## 5. 運営者が次に行うこと
1. ステージングでマイグレーション `20261116160000_marketing_post_types_quality.sql` を適用（本番は許可後）
2. `/admin/marketing` でカレンダー投入 → 本文を自分の声に直す → 承認
3. 手動でXに投稿（Buffer実送信はまだゲートOFF）
4. UTM付き投稿の流入をダッシュボードで確認し、時間帯仮説を更新
5. 週次雑談をやるなら日程確定後にだけ告知
